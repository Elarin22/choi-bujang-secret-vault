### 조치 SQLite 백업 절차(운영자 승인 후에만)

이 절차는 코드에서 확인한 파일 계약에 따른 계획이며 실제 경로·백업 도구·백업·복원은 확인하거나 실행하지 않았습니다. 담당자가 대상 경로와 보존 위치를 승인하고, 해당 호스트의 쓰기를 멈출 수 있는 유지보수 시간을 정한 뒤 진행합니다. SQLite CLI(`sqlite3`)와 그 버전도 실행 전에 별도로 확인해야 합니다. 아래 `$databasePath`와 `$backupDirectory`는 값을 출력하거나 문서에 기록하지 않고 승인된 경로로 로컬에서 지정하는 자리표시자입니다.

1. 호스트 담당자가 `sdpActionStartup.databasePath`와 승인된 프로젝트 외부 백업 디렉터리를 확인합니다. 연결 경로를 확인할 수 없으면 작업을 중단하고 담당자에게 요청합니다.
2. 앱/호스트의 쓰기 프로세스를 정상 종료해 DB 연결을 닫습니다. 파일이 사용 중이면 복사·복원을 진행하지 않습니다. 다른 사람의 프로세스를 임의로 종료하지 않습니다.
3. 승인된 백업 디렉터리에 시각이 포함된 별도 파일명을 정하고 SQLite 온라인 백업 명령으로 전체 DB 파일을 백업합니다. DB에 다른 테이블이 있을 수 있으므로 조치 테이블만 따로 떼어 백업하지 않습니다.

```powershell
$databasePath = '<담당자가 확인한 기존 SQLite 파일 경로>'
$backupDirectory = '<승인된 프로젝트 외부 백업 디렉터리>'
$backupPath = Join-Path $backupDirectory ("actions-{0}.sqlite" -f (Get-Date -Format 'yyyyMMdd-HHmmss'))
sqlite3 $databasePath ".backup '$backupPath'"
if ($LASTEXITCODE -ne 0) { throw 'SQLite 백업 실패: 담당자에게 확인하세요.' }
sqlite3 $backupPath 'PRAGMA integrity_check;'
```

4. 무결성 검사 결과가 `ok`인지 확인합니다. 백업 파일이 생겼다는 사실만으로 복구 가능성을 확인했다고 기록하지 않습니다. 승인된 접근 제어가 적용된 위치에 원본과 별도로 보관하고, 허용된 보존 기간과 접근 권한은 담당자 정책을 따릅니다.

### 복원 절차(담당자 승인 및 복구 사유 확인 후)

1. 먼저 복원 대상·시점·영향 범위를 승인받고, 현재 DB와 백업 파일을 각각 보존합니다. 복원은 전체 SQLite 파일 교체이므로 백업 시각 이후의 조치 상태·감사 이력이 사라질 수 있습니다. 이 손실 가능성을 승인하지 못하면 중단합니다.
2. 앱/호스트 쓰기 프로세스를 정상 종료하고 DB 연결이 닫혔는지 확인합니다. 다른 사용자의 실행을 임의로 중지하지 않습니다.
3. 복원 직전 현재 DB를 위의 `.backup` 절차로 별도 보존합니다. 승인한 복구본을 확인한 뒤 SQLite CLI의 `.restore`로 기존 대상 파일에 복원합니다. 파일 경로가 불일치하거나 도구가 오류를 반환하면 앱을 재시작하지 말고 담당자에게 넘깁니다.

```powershell
$preRestorePath = Join-Path $backupDirectory ("pre-restore-{0}.sqlite" -f (Get-Date -Format 'yyyyMMdd-HHmmss'))
sqlite3 $databasePath ".backup '$preRestorePath'"
if ($LASTEXITCODE -ne 0) { throw '복원 전 DB 보존 실패: 복원을 중단하세요.' }
sqlite3 $databasePath ".restore '$backupPath'"
if ($LASTEXITCODE -ne 0) { throw 'SQLite 복원 실패: 앱을 시작하지 말고 담당자에게 확인하세요.' }
sqlite3 $databasePath 'PRAGMA integrity_check;'
```

4. 무결성 검사에서 `ok`를 확인한 뒤 담당자가 승인한 읽기 전용 확인으로 예상 테이블과 업무 자료를 확인합니다. 이상이 있으면 서비스를 시작하지 않고 복원 전 사본을 보존한 채 담당자에게 보고합니다. 확인을 마친 뒤에만 담당자 승인으로 서비스를 재시작하고 상태 조회를 확인합니다. 조치 재실행이나 테스트 집행으로 복원을 검증하지 않습니다.

### 현재 확인 결과와 제한

- 원본 작업 폴더와 Git 기록을 유지했고 재현에는 별도 clone을 사용했습니다. clone은 커밋된 파일만 가져오며 원래 폴더의 미커밋 작업을 옮기지 않습니다.

- 조치 DB 경로, 실제 사용자 데이터, SQLite CLI 설치·버전, 담당자의 운영 백업 승인 절차는 미확인입니다. 이 PC에서 DB 백업·복원 또는 무결성 검사를 실행하지 않았습니다.
- 외부 계정·SDP·XDR·AI 서비스 데이터의 백업·복원 권한과 보존 주기는 서비스 담당자의 절차에 속하며 이 프로젝트에서 검증하지 않았습니다.
- 재현 중 데이터 삭제, 실제 조치 집행, 외부 계정 연결, DB 수정을 수행하지 않았습니다.
