# Heeeyaazz 시연 순서와 작업 정리

## 문서 범위와 증거 구분

이 문서는 현재 확인한 소스 커밋, 사용자가 제공한 화면 캡처와 PowerShell 기록을 구분해 정리합니다. 화면 캡처는 캡처 시점의 관찰이며 현재 값이 아닙니다. 소스 코드를 읽은 사실은 기능을 실제 실행했다는 증거가 아닙니다.

| 근거 종류 | 확인 내용 | 이 근거로 말할 수 없는 것 |
|---|---|---|
| 소스 확인 | 기준 커밋 8830251cfb9114486f23a81694d1e952d06c2456의 앱·학생 코드와 실행 문서를 확인했습니다. | 현재 커밋에서 브라우저 시연을 끝냈다는 뜻이 아닙니다. |
| 화면 캡처 | 사용자가 제공한 보호 현황 및 내 PC 상태 화면을 확인했습니다. 캡처에 나타난 값과 오류 문구는 아래에 캡처 시점의 관찰로 기록합니다. | 캡처가 기준 커밋에서 생성됐다는 연결 증거는 없습니다. 현재 PC 값으로 재사용할 수 없습니다. |
| Git 기록 | 사용자가 제공한 PowerShell 결과에 저장소 주소, 깨끗한 작업 트리, git push의 Everything up-to-date가 있습니다. | 앱 서버 실행이나 브라우저 기능 확인을 증명하지 않습니다. |
| 이전 재현 기록 | STUDENT_CLEAN_REPRODUCTION.md에는 커밋 eeffa481ed2de880260d5b54735420a8d0cb7224에서 로컬 서버 시작·종료를 확인한 기록이 있습니다. | 기준 커밋 8830251…의 실행 결과로 합산하지 않습니다. |

문서 작성 전 기준 커밋은 main에서 origin/main과 일치했고 작업 트리는 깨끗했습니다. 이 새 문서는 해당 커밋에 아직 포함되지 않았습니다. 이 문서 추가 이후에는 작업 트리가 변경된 상태입니다.

## 핵심 기능 3가지 시연 순서

### 1. 보호 현황 대시보드

1. 아래 실행 절차대로 앱을 시작하고 브라우저에서 http://127.0.0.1:5189/을 엽니다.
2. 보호 현황에서 상단 네 카드(사용자·세션, 현재 기기, 업무 앱 판정, 연결·자료 상태)와 아래 기록 추이·최근 보안 기록을 보여 줍니다.
3. 값이 실제 응답이면 화면의 상태를 그대로 읽습니다. 연결 없음·요청 실패·확인 불가이면 그 상태 자체를 보여 주며 성공으로 바꾸어 말하지 않습니다.

확인 근거: 사용자 제공 화면 캡처에서 대시보드 카드와 기록 영역이 보였고, 일부 자료 영역에는 연결 오류가 표시됐습니다. 이 캡처로 정상 SDP 연결이나 실제 기록 수신을 주장하지 않습니다.

### 2. 내 PC 상태

1. 보호 현황에서 내 PC 상태 영역으로 이동합니다.
2. CPU·메모리·시스템 드라이브 값, 단위, 측정 시각과 출처 표식을 보여 줍니다.
3. 네트워크·방화벽·Windows 로그 항목은 화면에 실제 표시되는 상태를 그대로 보여 줍니다. 캡처에 없는 값이나 확인 불가 항목을 추정해 채우지 않습니다.

캡처 시점에 실제 값으로 표시된 관찰(사용자 제공 화면, 2026-10-26, UTC+09:00):

| 항목 | 캡처에 표시된 값 | 측정 시각 |
|---|---|---|
| CPU 사용률 | 18.7% | 2026-10-26 17:27:54 |
| 메모리 | 사용 8.31 GiB / 전체 15.85 GiB (52.4%) | 2026-10-26 17:27:53 |
| 시스템 드라이브 C: | 사용 가능 211.56 GiB / 전체 465.65 GiB | 2026-10-26 17:27:53 |

이 값들은 캡처 시점의 실제 조회값이며 현재 상태를 나타내지 않습니다. 이 문서에는 설명용 예시 측정값을 실제 측정처럼 추가하지 않았습니다. 캡처에서 보이지 않은 네트워크·방화벽·Windows 로그 값은 미확인입니다.

### 3. 업무 앱과 보안 기록의 상태 확인

1. 업무 앱 메뉴에서 현재 화면이 제공하는 앱 선택·접근 요청 결과를 확인합니다.
2. 보안 기록 메뉴에서 목록·상세 표시를 확인합니다.
3. 실제 서버 결과가 없거나 실패하면 연결 오류·확인 불가를 그대로 설명합니다. 다른 사용자나 장애 상태를 만들거나 예제 자료를 실제 자료처럼 제시하지 않습니다.

현재 근거와 한계: 소스에서 메뉴와 학생 표시 연결을 확인했습니다. 제공된 화면 캡처에는 연결 실패·확인 불가 상태가 보이지만, 기준 커밋에서 업무 앱 판정 성공이나 실제 보안 기록 수신·필터·상세 조작을 직접 확인한 증거는 없습니다.

## 실행 및 시연 재현 절차

포장 명령과 설치 프로그램은 사용하지 않습니다. 프로젝트 폴더에서 직접 실행합니다.

    Set-Location 'C:\Users\user\Desktop\choi-bujang-secret-vault\on-client'
    node --version
    powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1

node --version은 v24.19.0이어야 합니다. 시작 도구가 안내한 URL을 브라우저에서 엽니다. 기본 포트는 5189입니다. 서버를 끝낼 때는 실행 중인 PowerShell 창에서 Ctrl+C를 누릅니다. 포트가 이미 사용 중이면 다른 프로세스를 종료하지 말고 실행 안내서의 대체 포트 절차를 사용합니다.

시연 체크 순서:

1. 보호 현황의 네 카드를 확인합니다.
2. 내 PC 상태의 현재 측정값·측정 시각·단위·출처를 확인합니다. 이 시각의 값만 실제 조회값으로 말합니다.
3. 업무 앱과 보안 기록으로 이동해 현재 표시되는 응답 또는 오류 상태를 그대로 확인합니다.
4. 브라우저에서 다시 불러오기를 눌렀다면 새 화면 결과를 확인합니다.
5. PowerShell의 Ctrl+C로 서버를 종료합니다.

### 2026-10-28 현재 코드의 로컬 실행

기준 코드 커밋 `8830251cfb9114486f23a81694d1e952d06c2456`의 `on-client` 폴더에서 실행했습니다. `node --version`은 `v24.19.0`이었습니다. 기본 포트 5189는 이미 사용 중이어서 다른 프로세스는 종료하지 않고 대체 포트 5190으로 시작했습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Port 5190 -Background
```

시작 도구가 `http://127.0.0.1:5190/`에서 HTTP 200을 확인했습니다. 같은 로컬 서버에서 `/api/local-system-metrics`와 `/api/diagnostics`도 응답했습니다. 브라우저 UI의 전체 메뉴 조작은 이번 실행에서 확인하지 않았습니다. 서버 응답만으로 SDP·AI 연결 성공을 뜻하지 않습니다. 포장·설치 명령은 실행하지 않았습니다.

| 기능 | 현재 확인 상태 | 구분 |
|---|---|---|

| PC CPU·메모리·디스크, 네트워크·방화벽·Windows 로그 | 이 실행에서 CPU·메모리·디스크·네트워크·로그 조회 성공, 방화벽은 `FIREWALL_CIM_UNAVAILABLE` | 기존 읽기 전용 기능. SDP 연결과 별도 |

권장 핵심 기능 3가지는 (1) 계정·기기·세션의 현재 상태, (2) 업무 앱 접근 판정의 결과·이유·시각, (3) 접속 기록·XDR 경보의 추이·필터·상세입니다. 셋 모두 학생 영역에 상태 표시가 있지만 현재 SDP가 연결되지 않아 실제 업무 자료로 검증하지 않았습니다.

PC 상태는 제공 대시보드가 CPU·메모리·디스크 값을 이미 보여 주므로 학생 영역에서 다시 수집하거나 복제하지 않습니다. 함께 다듬을 설명 기능은 **측정 방법·단위·측정 시각 안내**로 선택합니다. CPU는 1초 표본, 메모리는 운영체제의 물리 메모리 사용량, 디스크는 시스템 드라이브 여유 공간으로 설명합니다. 이 설명은 기존 화면에 있습니다.

실행 후 서버는 현재 포트 5190에서 동작 중입니다. 창 없이 시작했으므로 종료할 때는 시작 도구가 출력한 프로세스 번호를 작업 관리자에서 종료합니다. 다른 앱의 5189 포트는 그대로 둡니다.
